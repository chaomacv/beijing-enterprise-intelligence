    01 / SELECT

    文件太多，先看什么？

    先让模型理解文件的主题与结构，再决定哪些内容值得完整处理。

    1. 识别与抽样

      按实际内容识别格式，组织文件名、表头、首部、中部、尾部和固定种子随机样本。

    2. 本地模型判断相关性

      结合企业主体、事件本体和样本语义，给出保留、排除或不确定判断。

    3. 完整保留决策依据

      保存卡片、模型原回复与判断。不确定项继续规划或复核，排除也有台账。

    02 / EXTRACT

    表格太长，怎样分开看？

    模型制定字段方案，程序执行结构化处理；复杂内容再按完整记录交给模型。

    1. 分块携带共同语境

      完整行保留原值与记录编号，表头、单位、前置说明随块关联。

    2. 按实际 token 预算拆批

      预留输出空间。优先减少每批记录数，长文本采用有位置的片段或可重建视图。

    3. 逐条核对并保存检查点

      检查记录归属、主体和证据引用；失败缩批、重试或明确复核，已通过结果落盘。

    输入
    完整记录、字段方案、表头和上下文
    输出
    主体／事件候选、原文引用及逐条处理状态

    03 / RESOLVE

    名称相近，是同一家吗？

    先核对可靠标识，再检查名称与地址。证据不足时保留独立主体与复核候选。

    1. 可靠代码优先，冲突阻止归并

      验证信用代码的结构和校验位，明确冲突不因名称相似而被覆盖。

    2. 完整名称与非空地址作弱证据

      缺码记录只有满足保守条件才关联；同名缺地址继续保留独立归属。

    3. 相似度用于召回候选

      保存匹配依据与原始来源。暂定身份、事件阶段和来源质量随画像继续保留。
