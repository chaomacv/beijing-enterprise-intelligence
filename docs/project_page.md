# Project Page

Project Page 源码位于 `showcase/`，部署地址为 https://chaomacv.github.io/beijing-enterprise-intelligence/ 。README 开头提供入口与预览图。

页面以“分散的数据，有据可查的企业情报”为主线，展示文件筛选、结构分块和企业归并的方法选择。视觉参考 Observable 的可探索文档、留白与数据图形；参考 RailMind 和 experience-guided-code-agent 的项目介绍结构。页面代码和图形独立实现，不复制参考站点的代码或资源。

2026-11-09 根据用户标注参考图进一步改版：首页采用深色背景向白色渐变，首屏下方为七张大型数据笔记本，中央卡片完整显示，两侧露出相邻卡片。轮播默认每张约 8 秒，提供时间进度、页码、前后切换及暂停；悬停、键盘阅读、触摸操作、离开可视区或后台标签页时暂停。系统启用减少动态效果时默认不自动播放。

七张卡片分别展示格式／解析状态层级、事件类别与阶段、精确内容复用、三维文件分箱、记录处理状态、主体身份及实际执行时间线。统计图可筛阶段并切换对数刻度；三维图可拖动或用滑块旋转；时间线按真实时间间隔回放已核对快照。它们使用 SVG 和浏览器原生交互独立实现，没有加载远程图表库。

轮播窗口限制在居中的页面区域，宽屏显示三张完整卡片及两侧有限的预览，卡片约 720px 高。首尾循环通过移动已有节点并补偿滚动位置实现，不克隆表单或图表，不产生重复 ID；查看最后一张后，下一张继续向前到第一张。平板和手机保留单张主卡及侧边预览。卡片可放大阅读，关闭后保留原控件状态。

方法选择区改为三个原位分页：文件筛选、结构抽取、主体关联。每页包含输入／输出、三步方法说明、代码或条件示意、图形与合成结果，提供标签、前后翻页及方向键／Home／End。它们继续链接到已有交互实验，分页本身不跳转页面。

## 页面内容与数据

- `index.html` / `style.css`：中文项目介绍、方法、交互实验、证据追溯、九步流程、工程案例和复现入口。
- `model.js` / `app.js`：无第三方前端依赖的浏览器交互。抽样和分块实验是原理示意，不报告 token 节省或语义召回率。
- `run.js` / `assets/run-summary.json`：全量运行的汇总快照。九步导航说明各步输入、方法、中间产物及对应版本源码；每步支持鼠标和方向键切换。快照只含汇总数字，不连接私有处理服务。
- `assets/demo.json`：由仓库现有 Python 规则基线生成，包含 3 份合成文件、5 条记录、2 个暂定企业主体和 3 条事件。
- `assets/project-preview.svg`：README 的独立绘制预览图，图形是方法示意。
- `assets/notebook-*.svg`：三份独立绘制的静态合成图形，不依赖远程图片、字体或可视化库。
- `gallery.js` / `assets/gallery-data.json`：大型轮播与真实汇总分析；只包含计数、分箱和已核对的执行时间点，不含文件名、路径、业务记录或私有接口。
- `methods.js`：方法说明的三页切换、键盘操作与合成抽样图示。

交互实验和企业证据案例均为合成示例；实际规模与工程对照在对应区域单独标明。没有把真实业务明细、下载会话、服务器路径、凭据或模型推理日志放入页面。页面不调用模型服务，也不接受业务文件上传。当前全量运行尚未完成，画像、事件等最终数量为空；完成总对账前不会展示最终结果。

首页卡片另使用两种明确区分的真实汇总范围：文件层级和三维空间基于本批 11,701 个逻辑文件，包含展开成员与派生结果；事件、处理状态和身份基于已完成的 1,884 个字段方案文件、14,419,963 条来源记录子集。子集覆盖与未来全量结果重叠，不能相加。时间线是工程执行快照，不是企业事件日期分布；空间图是文件特征空间，不是企业地理位置。临时画像、来源事件阶段和待复核状态继续保留解释。

`scripts/build_gallery_data.py` 使用标准库从私有文件索引、阶段汇总、已公开的运行口径及人工核对的进度点生成白名单汇总。生成后由 `scripts/test_gallery.cjs` 检查分母、总数、字段和来源限制。CI 直接核对已提交汇总，不读取私有输入。

事件统计使用 `--classification-summary` 输入的修正汇总。旧“许可资质”5,031,890条分为十类，默认展示细分结果，可切换全部事件、阶段、对数刻度和关联画像数。画像数按类别／所选阶段去重，不能跨类别或阶段相加为企业总数。图表和 README 预览图使用同一修正口径，独立有效证照数量留空。详细边界见[分类修正说明](event_classification.md)。

三条工程笔记解释实际方法选择：完整内容精确复用仍保留每条来源；可重建的 HTML 文字视图仍绑定原字段；预算拆组后批量提交改善过长请求的串行回退。八条真实记录的耗时对照是单次工程实验，八条最终均进入复核，不能据此报告语义准确率或全量提速比例。向量召回的增益和独立标注评测仍待验证。

重新生成示例并验证：

```bash
python -m pip install -e .
python scripts/build_showcase_demo.py
node --check showcase/app.js
node --check showcase/run.js
node --check showcase/gallery.js
node --check showcase/methods.js
node --test scripts/test_showcase.cjs scripts/test_gallery.cjs scripts/test_methods.cjs
```

本地预览：

```bash
python -m http.server 8787 --bind 127.0.0.1 --directory showcase
```

浏览器打开 http://127.0.0.1:8787/ 。GitHub Pages 的项目子路径由相对资源链接支持，不需要构建器。

`Page browser checks` 在隔离的 Ubuntu 24.04 / Chromium 中运行桌面、宽屏、390px 和 320px 视口检查，测试三卡窗口、循环边界、计时播放、放大后的控件保留、方法区分页及横向溢出，并保存截图和失败 trace。Playwright 仅用于开发检查，不进入公开页面运行时；精确版本与依赖哈希保存在 `scripts/browser-qa/package-lock.json`。

## 发布与更新

仓库的 Settings → Pages → Build and deployment → Source 选择 GitHub Actions，然后运行 `Deploy project page` 工作流。之后修改页面或处理逻辑并推送 main 会重新生成合成示例、运行页面检查并发布。工作流仅上传 `showcase` 目录。

更新汇总快照时，需要核对[处理源码版本中的流程说明](https://github.com/chaomacv/beijing-enterprise-intelligence/blob/57748c4c4086432c4b129a0fee059018a1d6a4c1/docs/full_corpus.md)、私有运行验收和汇总字段口径。只有实际完成运行且总对账通过后，才设置完成状态、`final_audit_passed` 和 `final_counts`；独立语义准确率另作评测。禁止加入真实记录、模型输入或回复。当前合成案例中的“来源覆盖未知”“身份暂定”“拟议状态”应继续保留。

首屏操作区在桌面移至说明文字右侧，窄屏回到纵向排列。卡片参照用户提供的 Observable 截图：宽屏最高约620×720px，较窄桌面按三张完整卡片的窗口缩放宽度，手机保持单主卡。两处文案改为“本地模型、数据工程、可探索的公开信息”和“探索这次公开数据处理的每一面。”。

卡片控件更新：大卡片为直角，主题标签位于卡片外侧左上方，采用参考图中的凸出页签形式；右上独立放置对角角标扩展图标。桌面轮播采用 min(2200px,98vw)，大屏卡片最高约620×720px，较窄桌面仍保留三张主卡及侧边预览；手机高度640px。

首页副标题和介绍段落采用用户指定的企业事实／公共数据实践文案，主标题不含换行并随视口缩放为单行。删除轮播上方标题及说明，卡片区域上移。页面继续区分真实汇总、合成示例和未完成的准确率评测。

主标题在桌面字号增加三分之一（上限72px）；窄屏以单行不溢出为约束自适应。介绍与操作区增加64px上间距，连同轮播整体下移。卡片宽高按上一版的90%调整（桌面高度648px、手机576px），保留既有窗口。播放操作仅显示图标，倒计时文字移除，无障碍名称与轮播控制继续可用。
